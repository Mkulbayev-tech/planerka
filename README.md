# Бюджет семьи (Planerka)

Реализация макета Claude Design `budget-planner-v2.dc.html` (исходники макета — в `design/`) на Vite + React.
Приложение умеет работать в двух режимах:

- **Локальный демо-режим** — без настройки: один пользователь, данные в браузере, демо-сценарий из макета.
- **Общий семейный бюджет** — вход по почте, два (и больше) участника видят одни и те же траты, задачи, цели и доходы; обновления приходят сразу. Данные хранятся в Supabase (бесплатный тариф), свой сервер не нужен.

## Быстрый старт (демо)

```
npm install
npm run dev
```

## Мобильное приложение (iOS и Android)

Веб-код упакован в нативные приложения через Capacitor: папки `ios/` (проект Xcode) и `android/` (проект Gradle).
Название на экране — «Бюджет семьи», Bundle ID — `kz.planerka.app`. Иконка и сплэш генерируются из `assets/icon.png`
и `assets/splash.png` командой `npx capacitor-assets generate`.

- **Поставить на свой iPhone** (нужен Mac с Xcode и подключённый телефон):

  ```
  sh scripts/ios-install.sh "iPhone (Мэлс)"
  ```

- **Отправить партнёру через TestFlight** (нужен ключ App Store Connect API и запись приложения в App Store Connect):

  ```
  ASC_KEY_ID=… ASC_ISSUER_ID=… ASC_KEY_PATH=~/AuthKey_….p8 sh scripts/ios-testflight.sh
  ```

- **Android**: `npx cap open android` в Android Studio или `cd android && ./gradlew assembleRelease`
  (нужны Java 17 и Android SDK). Готовый APK появится в `android/app/build/outputs/apk/`.

**Виджеты iOS.** В проекте есть расширение WidgetKit (`ios/App/PlanerkaWidgets/`): «Бюджет» (средний), «Планы» и
«Накопления» (маленькие), «Обзор» (большой). Чтобы добавить: удерживайте пустое место на экране «Домой» → «+» (или «Изменить»
→ «Добавить виджет») → найдите «Бюджет семьи». Данные обновляются при каждом изменении в приложении через общий контейнер
`group.kz.planerka.app` (мост `ios/App/App/WidgetBridgePlugin.swift`).

**Что ещё умеет приложение.** «Напоминать вносить траты» ставит ежедневное уведомление в 20:00. «Экспорт в Excel» открывает
системное окно «Поделиться» с CSV-файлом. Аппаратная кнопка «назад» на Android закрывает форму или возвращает на главную.

После любых изменений в коде: `npm run build && npx cap sync`, затем пересобрать приложение.
Вход в приложении — по профилю (01 Айнур, 02 Мэлс) и паролю.

## Настроить Supabase заново одной командой

1. Создайте токен Supabase: https://supabase.com/dashboard/account/tokens → **Generate new token**.
2. Выполните в папке проекта:

   ```
   SUPABASE_ACCESS_TOKEN=sbp_... node scripts/setup-supabase.mjs --site=https://mkulbayev-tech.github.io/planerka/
   ```

   Скрипт создаст проект Supabase (или возьмёт существующий с именем `planerka`), применит схему, настроит вход по почте
   с кодом в письме, запишет ключи в `.env` и в секреты GitHub и запустит деплой. Через пару минут сайт переключится
   в режим общего бюджета.

Ниже — те же шаги вручную, если скрипт по какой-то причине не подошёл.

## Общий семейный бюджет: настройка за 15 минут

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (Free).
2. Откройте **SQL Editor → New query**, вставьте содержимое файла `supabase/schema.sql` и нажмите **Run**.
3. **Authentication → Providers → Email**: включён по умолчанию. Чтобы вход работал по коду из письма, откройте
   **Authentication → Email Templates → Magic Link** и добавьте в текст письма строку `Ваш код: {{ .Token }}`.
   Без этого вход работает по ссылке из письма.
   Встроенная почта Supabase отправляет всего несколько писем в час. Если письма не приходят, подключите свой SMTP
   (**Authentication → SMTP Settings**, например бесплатный тариф Resend).
4. **Authentication → URL Configuration**: в **Site URL** укажите адрес, где будет опубликовано приложение
   (например `https://planerka.vercel.app`), для локальной проверки добавьте `http://localhost:5173` в **Redirect URLs**.
5. **Project Settings → API**: скопируйте `Project URL` и `anon public` ключ в файл `.env`:

   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```

6. Соберите и опубликуйте статику:

   ```
   npm run build
   ```

   Папку `dist/` можно выложить на Vercel, Netlify или GitHub Pages. На Vercel/Netlify достаточно подключить репозиторий,
   указать команду сборки `npm run build`, папку `dist` и добавить те же две переменные окружения в настройках проекта.

7. Первый участник входит по почте, нажимает «Создать семейный бюджет» и находит **код приглашения** в разделе «Ещё».
   Второй входит по своей почте и нажимает «Присоединиться по коду».

На телефоне откройте ссылку в Safari/Chrome и выберите «Добавить на экран Домой» — приложение будет работать как обычное.

## Что где лежит

- `src/lib/dates.js` — даты: зарплатный период (с N-го числа), неделя, русские подписи.
- `src/data.js` — категории, темы, форматирование сумм, демо-данные.
- `src/model.js` — расчёт всего, что показывают экраны и виджеты (`derive(state, now)`).
- `src/lib/autoplan.js` — автораспределение дохода по лимитам (`planBudget`) и подбор категории по комментарию (`guessCat`).
- `src/lib/bills.js` — регулярные платежи; `src/lib/settle.js` — кто кому переводит; `src/lib/statement.js` + `src/lib/pdf.js` — импорт выписки Kaspi (PDF через pdf.js, грузится только при импорте) и CSV.
- `src/store.jsx` — состояние, действия, вход, подписка на обновления.
- `src/backend/` — хранилища: `local.js` (браузер) и `supabase.js` (общий бюджет). Выбор — по переменным окружения.
- `src/screens/` — экраны; `src/components/SheetHost.jsx` — формы задач, целей, доходов, лимитов, категорий, пароля.
- `src/widgets/WidgetsBoard.jsx` — доска iOS-виджетов; `src/ios-frame.jsx` — рамка iPhone из макета.
- `supabase/schema.sql` — таблицы, права доступа (RLS) и функции для Supabase.

## Разделы приложения

Внизу четыре вкладки и кнопка «+» (новая трата):

- **Аналитика** (`Home.jsx`) — сколько можно потратить до зарплаты, доходы и расходы, куда уходят деньги, кто сколько
  потратил; переключатель «Неделя / Месяц / Год». Плитка «Доходы» открывает доходы и зарплату.
- **Планы** (`Plans.jsx`) — задачи по дням (лента недели, «Мои / партнёр / Все») и цели накоплений с пополнением.
- **Расходы** (`Spend.jsx`) — потрачено за период из лимита, категории (тап — показать только их траты) и все траты по дням.
  «Лимиты и свои →» открывает лимиты и свои категории, «Распределить →» — автораспределение. Там же предупреждения
  о лимитах, регулярные платежи («Все →» — экран `Bills.jsx`) и «Загрузить выписку Kaspi».
- **Ещё** (`Settings.jsx`) — семья, доходы, лимиты, тема, напоминание, экспорт, пароль.

## Как устроены данные

- Период = зарплатный цикл: с «начала месяца» (по умолчанию 5-е число) до того же числа следующего месяца.
  Баланс «можно потратить» = зарплата + разовые доходы за период − траты за период.
- Тёмная тема и напоминания — настройки конкретного устройства; всё остальное общее для семьи.
- Планы личные: у каждой задачи есть владелец (в форме поле «Кому»: мне, партнёру или общая). На экране «Планы»
  переключатель «Мои / Айнур / Все», лента недели со стрелками и выбором любого дня; в форме задачи есть дата и повтор
  (каждый день на 30 дней, каждую неделю на 8 недель). Главная, дашборд и виджеты показывают задачи текущего профиля на сегодня.
- Категории трат: шесть встроенных и свои (кредит, рассрочка, связь…) — «+ Своя» на экране новой траты или
  «+ Новая категория» в бюджете. Своя категория общая для семьи, у неё есть цвет и необязательный лимит; удержание
  на ней в списке категорий траты или тап в «Лимитах и категориях» открывает изменение. Если по удалённой категории уже были траты, она пропадает
  из выбора, но остаётся в истории. Хранятся в `households.settings.cats`.
- Автораспределение («Расходы» → «Распределить →», «Лимиты и категории» или «Ещё»): из дохода периода сначала
  откладываются взносы в цели (поле «Откладывать в месяц»), потом обязательные платежи (Жильё и свои категории
  с «кредит», «рассрочка», «аренда», «связь», «коммунал»… в названии — их не урезает), остальное раскладывается
  по привычным тратам: средние за 3 прошлых периода, а пока их нет — темп трат этого периода. Лимит не бывает меньше
  уже потраченного плюс затраты невыполненных задач до конца периода. Около 5% дохода остаётся запасом; если денег
  не хватает, повседневные лимиты урезаются пропорционально. Режим «Урезать повседневные траты на 10% / 20%».
  Переключатель «Распределять автоматически» пересчитывает лимиты в начале каждого периода — первым открывшим
  приложение; настройки в `households.settings.autoPlan` `{ on, save, period }`.
- Категория новой траты подбирается по комментарию: сначала по прошлым тратам семьи с таким названием
  («Magnum» → куда относили раньше), потом по ключевым словам (такси, аптека, кофе, кредит…). Пометка «подобрано»
  в подписи; если выбрать категорию руками, подбор до конца этой траты отключается.
- Регулярные платежи (`settings.recurring`): название, сумма, число месяца (31 → последний день короткого месяца),
  категория, кто платит. В свой день трата вносится сама — первым открывшим приложение телефоном; id траты
  `rec-<платёж>-<дата>`, поэтому второй телефон дубль не создаст (`insertMany(…, { skipExisting })`), а дата пишется
  в `done` — удалённую вручную трату приложение не вернёт. Прошлые даты до добавления платежа не вносятся. Напоминание
  в 10:00 в день платежа (если напоминания включены). Неоплаченные платежи периода идут в план автораспределения,
  их категории считаются обязательными.
- Предупреждения о лимитах: когда категория доходит до 80% или превышает лимит (своей тратой, тратой партнёра,
  импортом или регулярным платежом) — вибрация и сообщение; на «Аналитике» и «Расходах» карточка с такими категориями.
- Остаток месяца в цель (`settings.sweep`): в начале периода доход прошлого минус траты и уже отложенное уходит
  в выбранную цель. Включили посреди периода — прошлый остаток только кнопкой «Отложить сейчас». Разовое действие
  «захватывается» через `settings.claims` (`backend.claim`), чтобы не случилось дважды на двух телефонах.
- Расчёт между двумя участниками: все траты с автором делятся поровну или 60/40, 70/30 (`settings.split.share` —
  доля участника с меньшим user_id); «Перевод сделан» пишет перевод в `settings.settle.log`. На «Аналитике» под
  «Кто сколько потратил» — строка «А → Б · сумма».
- Импорт выписки («Расходы» или «Ещё»): PDF Kaspi Gold (строки «Дата ± Сумма ₸ Операция Детали») или CSV (наш
  экспорт или банковский с колонками «Дата» и «Сумма»). Категории подбираются как для новой траты, их можно
  поменять; переводы, снятия и поступления по умолчанию не отмечены; трата с той же суммой в тот же день помечается
  «похоже, уже есть». id строки — хеш содержимого, повторный импорт того же файла ничего не задвоит.
- Долгое нажатие на задаче открывает редактирование, тап — отмечает выполненной. Тап на трате, доходе,
  цели или категории бюджета открывает карточку с изменением или удалением.
